# Codex agent tasks

This is the implementation dispatch and status index. The analysis task originally left every task planned; the active rewrite goal now executes the waves below. Completion requires reviewed evidence at an integrated revision.

## Coordination rules

Before implementation, follow [reference coding](reference-coding.md): search the project contract and relevant pinned repositories in XERJ, read the original implementation and adjacent tests, and record query, commit, file/line, findings and adaptation in the task worklog. The integrator owns pin refreshes and shared index rebuilds. Use the verified project search helper; read its documented XERJ limitations before substituting native CLI queries.

Use one integrator and at most three active workers at a time. Agent roles below can be reused across several waves; eight roles do not mean eight simultaneous agents. In separate Git worktrees, integrate dependency revisions before starting dependent work. In a shared checkout, claim exact files and use the ownership table to avoid simultaneous edits.

The integrator owns task status, shared model changes, dependencies/lockfile, root module declarations, CI definitions, and final integration. Workers own their feature modules and colocated unit tests. Database regression additions use task-specific files such as `tests/cases/t12_recovery.rs`; the QA owner maintains the common harness and fixture manifest. Submit fixture/baseline changes for review instead of silently regenerating expected results.

Before coding, locate and read the user-required **rtk** and **ponytail** skills/guidance in the active environment. Use RTK command wrappers where supported and Ponytail's smallest-complete-solution approach. This analysis found Ponytail's skill and RTK's installed guidance, but no separate RTK `SKILL.md`; verify availability in the implementation environment and record a limitation if still missing. Do not install tools, expand features, or claim skill execution merely to satisfy a checklist label.

Freeze shared structures through T01 fixtures. A worker needing a contract change sends a concrete proposed type/fixture diff to the integrator and continues independent work. The integrator merges the change once and identifies affected consumers. Give temporary ownership of a cross-module file to one worker explicitly; do not have several agents “fix integration” in the same file.

Every task finishes with a [worklog entry](../worklog/TEMPLATE.md), appropriate passing checks, and a handoff containing revision, files, commands/results, limitations, and next dependency. A blocked task records the exact missing prerequisite and leaves unaffected tasks available. Only the integrator changes the task board.
