# Ora2Pg ideas for My2pg

Source review: 2026-10-27. Ora2Pg checkout: `d53a3dfd5930788098f2e178a8fd006c9eabcaa9`, clean when inspected. My2pg baseline: `5ec4034d350309fc2d631f8c437748e5f14d915e`. This compares source behavior; it does not certify an Ora2Pg migration or benchmark either tool.

Ora2Pg is a Perl migration tool with Oracle, MySQL/MariaDB and SQL Server paths. Its MySQL adapter is relevant here; Oracle SCN, PL/SQL conversion and other source adapters do not change our [MySQL-only scope](scope-and-compatibility.md). Its most useful ideas are an inventory before migration, an explicit mapping policy, separate structure/count/data validation, and a repeatable operator workflow. We should apply these ideas through our existing planner, reports and tests.

The reference is GPL-3.0. Keep it read-only and use independent Rust implementations and synthetic test cases. This review does not propose copying Perl code, fixtures or adding Ora2Pg as a runtime dependency. [License](https://github.com/darold/ora2pg/blob/d53a3dfd5930788098f2e178a8fd006c9eabcaa9/LICENSE)

## Findings and decisions

| Idea found in Ora2Pg | My2pg comparison and decision |
| --- | --- |
| Inventory tables, views, triggers, indexes, functions and procedures before estimating migration work. `_get_objects` enumerates MySQL object kinds; SHOW_REPORT explains unsupported objects. | Reuse our existing source catalog and diagnostics for an understandable readiness summary. Keep objects requiring manual migration visible. Do not attach Oracle-oriented person-day estimates to MySQL work without calibrated evidence. [MySQL inventory](https://github.com/darold/ora2pg/blob/d53a3dfd5930788098f2e178a8fd006c9eabcaa9/lib/Ora2Pg/MySQL.pm#L1830-L1924), [report workflow](https://github.com/darold/ora2pg/blob/d53a3dfd5930788098f2e178a8fd006c9eabcaa9/doc/Ora2Pg.pod#L3070-L3144) |
| MySQL-specific type mappings and configuration overrides are centralized. Unsigned integer types widen rather than always using signed equivalents. | Already present in `plan::builtin` and ordered casts. Retain exact unsigned ranges, DECIMAL precision/scale and explicit narrowing refusal. Do not adopt Ora2Pg's default TIME-to-time or TIMESTAMP-without-time-zone mapping; our signed durations, UTC instants and declared fractional precision are intentional. Ora2Pg's `_sql_type` also removes explicit TIME/TIMESTAMP precision from its input type string. [Mapping table](https://github.com/darold/ora2pg/blob/d53a3dfd5930788098f2e178a8fd006c9eabcaa9/lib/Ora2Pg/MySQL.pm#L20-L62), [type conversion](https://github.com/darold/ora2pg/blob/d53a3dfd5930788098f2e178a8fd006c9eabcaa9/lib/Ora2Pg/MySQL.pm#L1257-L1376) |
| Discover default/nullability/generated-column metadata and source AUTO_INCREMENT counters. | Already present, with additional native tests for metadata loss, empty tables, binary defaults and source sequence floors. Keep original character-default bytes separately from decoded metadata; do not regress to copying `COLUMN_DEFAULT` blindly. Our sequence adjustment also retains a higher existing next value, checks exhaustion and never treats uncertain `setval` effects as rolled back. [Column discovery](https://github.com/darold/ora2pg/blob/d53a3dfd5930788098f2e178a8fd006c9eabcaa9/lib/Ora2Pg/MySQL.pm#L349-L464), [counter discovery](https://github.com/darold/ora2pg/blob/d53a3dfd5930788098f2e178a8fd006c9eabcaa9/lib/Ora2Pg/MySQL.pm#L2115-L2153); My2pg: [reader](../src/mysql/mod.rs), [sequences](../src/postgres/sequences.rs) |
| Separate `TEST`, `TEST_COUNT`, and `TEST_DATA` operations. | Adopt the principle that schema/count success is distinct from content equality. We already have counts/schema, exact content verification for a declared subset, and standalone saved-run verification. Extend the subset rather than reporting an unsupported type as verified. Binary columns are the immediate gap. [Validation actions](https://github.com/darold/ora2pg/blob/d53a3dfd5930788098f2e178a8fd006c9eabcaa9/doc/Ora2Pg.pod#L844-L853); My2pg: [canonical values](../src/verify/canonical.rs), [live comparison](../src/verify/content.rs) |
| TEST_DATA normalizes selected representations, such as booleans and numeric trailing zeros, before comparison. | Use explicit type-aware normalization only where the resolved migration contract proves equivalence. Ora2Pg's code joins row values using a separator; retain our type/null tags and length framing, which distinguish NULL, empty bytes and embedded delimiters. Native tests must compare independent source/target values and detect equal-count corruption. [Comparison loop](https://github.com/darold/ora2pg/blob/d53a3dfd5930788098f2e178a8fd006c9eabcaa9/lib/Ora2Pg.pm#L22912-L22987) |
| Data validation defaults to the first 10,000 rows, with zero meaning all rows; ordering normally requires a PK/UNIQUE key. | Keep full comparison for supported types and our duplicate-preserving external-sort multiset for keyless tables. A sample can be useful as a separately labelled future diagnostic, but cannot satisfy complete migration validation. Neither a matching sample nor a whole-table hash proves exact equality; our current multiset compares full canonical rows. [Documented limits](https://github.com/darold/ora2pg/blob/d53a3dfd5930788098f2e178a8fd006c9eabcaa9/doc/Ora2Pg.pod#L1994-L2014), [query limits and ordering](https://github.com/darold/ora2pg/blob/d53a3dfd5930788098f2e178a8fd006c9eabcaa9/lib/Ora2Pg.pm#L22593-L22625), [source/target LIMIT construction](https://github.com/darold/ora2pg/blob/d53a3dfd5930788098f2e178a8fd006c9eabcaa9/lib/Ora2Pg.pm#L22818-L22907) |
| Defer index/constraint creation to make initial bulk loads efficient; generated scripts stop on SQL errors by default. | Already implemented through required DDL phases and fatal finalization errors. Preserve existing-target constraint/trigger semantics; do not automatically drop their indexes, disable RI triggers or change foreign-key deferrability to obtain speed. [Stop/COPY options](https://github.com/darold/ora2pg/blob/d53a3dfd5930788098f2e178a8fd006c9eabcaa9/doc/Ora2Pg.pod#L1939-L1953), [constraint/index options](https://github.com/darold/ora2pg/blob/d53a3dfd5930788098f2e178a8fd006c9eabcaa9/doc/Ora2Pg.pod#L2382-L2430) |
| Parallelism has separate table/job controls. | Already implemented with stronger global byte/socket admission and bounded queues. Ora2Pg documents that processes multiply across those controls; retain a single global resource contract instead of multiplying concurrency unknowingly. COPY FREEZE is a restricted performance experiment, not an immediate compatibility change: our current CREATE and batch COPY transactions do not meet its documented same-subtransaction condition. [Parallel controls](https://github.com/darold/ora2pg/blob/d53a3dfd5930788098f2e178a8fd006c9eabcaa9/doc/Ora2Pg.pod#L1040-L1055), [FREEZE constraints](https://github.com/darold/ora2pg/blob/d53a3dfd5930788098f2e178a8fd006c9eabcaa9/doc/Ora2Pg.pod#L1945-L1953) |

Do not adopt an automatic fake date, zero-to-NULL, trimming, float rounding or boolean inference policy. Arbitrary source SQL transformations and source-side helper installation remain excluded. [Zero dates](https://github.com/darold/ora2pg/blob/d53a3dfd5930788098f2e178a8fd006c9eabcaa9/doc/Ora2Pg.pod#L1605-L1611), [transformation mechanism](https://github.com/darold/ora2pg/blob/d53a3dfd5930788098f2e178a8fd006c9eabcaa9/doc/Ora2Pg.pod#L2016-L2024) |

## Concrete gaps found in our baseline

1. **Bytea content verification is unsupported.** The loader already preserves binary/text-to-bytea values and defaults, but `canonical::kind_tag` rejects `ValueKind::Binary`. This prevents complete built-in content verification of otherwise ordinary BLOB/VARBINARY migrations. Extend exact canonical bytes, preserve framing and bounded storage, and include explicit supported binary transforms. [Implementation](../src/verify/canonical.rs), [existing independent byte oracle](../tests/cases/t10_text_bytea.rs)
2. **Routine discovery and planner severity disagree.** `mysql/unsupported.sql` produces `function`/`procedure` kinds; `plan::build` recognizes only `routine`/`event`/`trigger` as manual-inventory warnings. Actual MySQL functions/procedures therefore become blocking errors even though the documented scope says manual migration. Classify the actual kinds consistently, retaining strict errors for unsupported table/index/storage semantics. Keep warnings visible and keep routine execution/translation excluded. [Discovery](../src/mysql/unsupported.sql), [planner](../src/plan/mod.rs), [scope](scope-and-compatibility.md)
3. **Blocked-plan output loses actionable detail.** The pipeline converts planner diagnostics to a list of codes, discarding object names and remediation messages from the error displayed to the operator. Ora2Pg's report-oriented workflow suggests a useful improvement to the existing CLI, without adding a second configuration system. [Pipeline boundary](../src/pipeline/mod.rs)

These are source findings at the baseline revision. Current implementation status and runtime proof belong in the coordinator's task worklog and task board.

The first two gaps are now implemented and validated in [the adaptation worklog](../worklog/2026-10-27-ora2pg-quality.md): binary verification runs through the real CLI and standalone verification, and a native function/procedure catalog fixture reaches planning as visible warnings. The remaining diagnostic/readiness work below is still a backlog.

## Evidence boundary

The inspected Ora2Pg checkout has no tracked `t/` or `tests/` test suite and no test entries in `MANIFEST`. Its `TEST*` commands are runtime migration-validation tools, not evidence that its own conversion implementation passed an automated regression suite. This review read their implementations and documentation; it did not install Perl dependencies, run upstream setup scripts, or run Ora2Pg against databases.

Broader performance claims, version/platform certification, Oracle-only features, CDC/catch-up, automatic resume, SQL-routine translation, source writes and online cutover remain outside this adaptation. Continue using our [reference workflow](reference-coding.md), [acceptance checklist](checklists.md), and [task ownership](agent-tasks.md).
