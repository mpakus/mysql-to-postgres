# T15 — reject-budget assertion race

## Reference research before edit

- XERJ project query `OwnedRejectTicket RawRetention budget used weak upgrade drop flight` against `project-my2pg` at indexed revision `db28c459a8a3caf45b07e9e72bcbc9fd3194c762` returned `src/report/artifact_io.rs:421,601`, the `Flight` retention/ticket paths, and `tests/cases/t15_artifact_io.rs:541,661,721`.
- Pinned `ref-rust-postgres` query `async task drop owned state acknowledgement channel cleanup` at commit `1084ca8f5b5302e161892f2fa40abf71b4060c10` returned `tokio-postgres/src/copy_in.rs:181-199` and adjacent tests; it sends COPY completion through protocol messages but has no shared reject-budget ticket/retention release pattern to reuse. Pinned `ref-mysql_async` query `drop result stream connection resource test` at commit `d7525dcb1d35f3d60101a2e95e84171c3d3ac4a5` returned `conn/pool/mod.rs:361-386`; that synchronous connection-return path is not applicable. No reference code is adapted.
- Read the current original implementation and adjacent tests: `src/report/artifact_io.rs:421-465,601-619,1166-1249,1273-1358,1502-1535` and `tests/cases/t15_artifact_io.rs:370-650,700-775`. `Flight` declares `retention` before `ticket`; the ticket decrements the shared counter from `Drop` unless committed. The test waits for the raw-permit `Weak` to expire, then reads the separate budget counter.
- Reproduction: the first full all-target/all-feature run failed with `budget.used() == 2` where 1 was expected. The correctly filtered isolated test and the three-test T15 artifact-I/O group passed. In ten repetitions of the full serialized integration binary, one run failed at this assertion and nine passed; the failure is order/timing-sensitive. Rust Reference confirms struct fields drop in declaration order: <https://doc.rust-lang.org/reference/destructors.html>.
- Decision: preserve both expectations and wait under the existing bounded deadline until the raw-retention weak reference is gone **and** the uncommitted ticket decrements the budget. Add an assertion message with the observed count on timeout. Apply this at both equivalent test sites; do not alter production ownership or weaken the budget expectation. The focused integration test and repeated full integration runs must pass afterward.
- RTK and Ponytail guidance were read before this edit. No `CONTEXT.md` or ADR was present in the project inventory.

## Fix and verification

- Updated both shutdown/failure wait loops in `tests/cases/t15_artifact_io.rs` to wait until the raw permit is released and `budget.used()` returns to the one durable reject. The bounded deadline now reports the lingering count if ticket release does not complete. No production code or behavior changed.
- The focused case passed once after the edit. Before the edit, one of ten full integration-binary executions failed at this exact assertion; after the edit, ten consecutive full serialized integration-binary executions passed (17 passed, 142 ignored each).
- `rtk run './bin/cargo fmt --all -- --check'` passed; `rtk run './bin/cargo clippy --offline --locked --all-targets --all-features -- -D warnings'` passed.
- `rtk run './bin/cargo test --offline --locked --all-targets --all-features -- --test-threads=1'` passed: library 126 passed/3 ignored; binary 1 passed; contracts 15 passed; driver 1 passed/11 ignored; importer 18 passed; integration 17 passed/142 ignored; NLS 0 passed/1 ignored. Database- and platform-gated cases remain unexecuted by this command and are not release-lane evidence.
- The Rust Reference states that struct fields drop in declaration order: <https://doc.rust-lang.org/reference/destructors.html>. This explains why observing one field's `Weak` expire does not synchronize on the separate ticket field's `Drop`; the test now waits for both conditions.
