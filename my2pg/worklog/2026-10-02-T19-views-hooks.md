## Adaptation and acceptance

Preserve the MySQL-only v1 contract: explicitly selected existing views are read as evaluated row snapshots into ordinary PostgreSQL tables; do not create or drop MySQL objects, and allow selected views under the source's read-only snapshot consistency because a view has no storage engine of its own. Hook plans contain ordered paths and SHA-256 digests; planning/checking only reads and hashes SQL, never executes it. Run hooks only through the PostgreSQL connection, verify their bytes still match the planned digest immediately before execution, run `before` hooks before target DDL, and run `after` hooks only after load and finalization succeed. After hooks run before verification so verification covers their effects. A hook error fails the run; an unsuccessful load cannot reach after hooks.

Acceptance includes plan tests for selected vs unselected views and ordered hook digests, plus native integration tests proving a view's evaluated rows are copied without source DDL, planning has no target side effects, hook order is observable, hook errors fail the run, and failed preparation suppresses after hooks. All test expectations are independent database observations.
