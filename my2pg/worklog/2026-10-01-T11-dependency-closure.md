## Proposed precise query contracts — before code

### Dependency graph

Inputs `$1::oid[]` selected relation OIDs and `$2::oid[]` requested existing type OIDs. Inputs are positive discovered identities in the same root-owned RR READ ONLY snapshot; no name parsing. Query adds all database event triggers as separately flagged roots. NULL/zero/missing object input does not silently become an empty successful selection: roots_valid=false, and root decoder must return Metadata error before any policy uses the graph. Empty non-NULL input arrays with no event triggers return a positive header-only record. Requested types are inspection/reuse roots, never implicitly selected DROP objects. Duplicate valid roots deduplicate; root counts use distinct OIDs.

Cycle-safe recursive UNION traverses all incoming pg_depend endpoints; whole object subid0 covers every referenced subobject, while reached columns retain exact nonzero subids. Also promote reached objects through outgoing INTERNAL i ownership so rewrite-rule→owning-view→outside dependent views/functions are included. Do not recursively follow ordinary outgoing namespace/type/function/role/extension edges into unrelated users. For every reached object, return all incident local edges plus current-database outgoing pg_shdepend edges. Outgoing endpoint details are preserved, but they are not incoming blockers. No recursion depth/row truncation that could make a partial inventory appear complete. Unknown classes/kinds stay raw or cause an explicit unsupported identity-query error; never silently skipped.

One row per reached object × incident edge; LEFT preserves no-edge headers. Always-one header carries required `database_oid:u32`, `selected_relation_count/requested_type_count/event_trigger_count:i64`, `roots_valid:bool`. Node aliases: `node_class_oid/node_oid:Option<u32>`, `node_sub_id:Option<i32>`, `node_catalog/node_type/node_schema/node_name/node_identity:Option<String>`, `selected_relation_root/requested_type_root/global_event_root:bool`. Empty header nodeNone is not a zero-valued object or zero edge.

Additional optional node provenance: `node_owner_relation_oid/node_owner_role_oid/node_extension_oid:Option<u32>`, `node_owner_column_ordinal:Option<i16>`, `node_owner_relation_schema/node_owner_relation_name/node_owner_role/node_extension_name/node_relation_kind/node_type_kind/node_constraint_kind/node_function_kind/node_function_definition/node_event_enabled/node_event:Option<String>`, `node_function_body_parsed:Option<bool>`. Relation owner mapping uses actual pg_index/pg_attrdef/pg_constraint/pg_trigger/pg_rewrite/pg_type/sequence-ownership OIDs; None means no proved selected-table owner, never inferred from namespace. Function definitions are inspected, not executed; aggregate prokind and all unknown raw flags remain visible.

Reuse existing optional dependency aliases/types, plus `dependent_class_oid/referenced_class_oid:Option<u32>` so actual graph keys are classOID/OID/subid. `dependency_catalog` identifies pg_catalog.pg_depend vs pg_catalog.pg_shdepend; `dependency_direction` is relative to the current reached node. Preserve dependent/referenced catalog, OID, subid, kind and object type/schema/name/identity exactly. Shared referenced_sub_id0 reflects absence of a pg_shdepend subobject field. Role names use permitted pg_roles. Whole-object edges referencing columns keep their actual nonzero endpoint and are matched by coverage, not rewritten.

Suggested root Rust wrapper: `TargetDependencyGraph { database_oid:u32, selected_relation_count:u64, requested_type_count:u64, event_trigger_count:u64, nodes:Vec<TargetDependencyNode>, edges:Vec<TargetObjectDependencyWithClassIds> }`; None in TargetCatalog means uninspected, Some(empty) means success/known-empty. Root decoder validates complete header/count/alias consistency, roots_valid and error propagation before setting observed. Optional row fields are transport encoding of header-only results; real object/edge structs require complete nonzero keys.

### Type inventory

Input `$1::text` exact namespace. LEFT type/enum/domain-check joins preserve every namespace/type header, including unused types and enums with zero labels. Successful missing namespace returns0 rows; existing empty namespace returns one row with type_oidNone. Required namespace aliases: `namespace_oid:u32`, `namespace_name:String`, `namespace_can_use/namespace_can_create:bool`.

Optional type aliases: `type_oid/type_owner_role_oid/type_relation_oid/type_element_oid/type_array_oid/type_base_oid/type_collation_oid/extension_oid:Option<u32>`, `type_schema/type_name/type_owner_role/type_kind/type_category/type_alignment/type_storage/type_default_expression/type_comment/extension_name:Option<String>`, `type_defined/type_by_value/domain_not_null/can_use/can_alter:Option<bool>`, `type_length:Option<i16>`, `type_modifier/domain_array_dimensions:Option<i32>`. Raw OID0 for absent pg_type links is kept inside present type headers, not silently reinterpreted as another type. Owner ALTER is separate from type USAGE/schema privileges.

Enum aliases `enum_label_oid:Option<u32>`, `enum_label:Option<String>`, `enum_sort_order:Option<f32>` ordered by actual enumsortorder thenOID, never lexical order or aggregate comma strings. Domain checks: `domain_constraint_oid:Option<u32>`, `domain_constraint_name/domain_constraint_kind/domain_constraint_definition/domain_constraint_expression:Option<String>`, `domain_constraint_validated/domain_constraint_deferrable/domain_constraint_initially_deferred:Option<bool>`. A known enum header with no label rows means Some([]); missing/uninspected type means unknown, and non-enum kind must not be interpreted as an empty enum. Actual domain/composite/array identities and constraints remain independent from planning expectations.

Adapt catalog discovery/owner promotion only, not deletion locks or CASCADE execution. No copied source code.

Root builds a **separate allowed-drop ownership closure** only from selected relation roots using incoming reviewed AUTO/INTERNAL ownership edges and observed actual table owner identities. Broad recursive discovery includes external NORMAL users and INTERNAL owner promotion solely to reveal blockers; discovery membership is not deletion authorization. Selected mutual FK constraints can be automatic children of selected owners even while referencing another selected table. Unselected views/functions/defaults/columns/types/sequences are not made selected by appearing in the graph. Extension e/x, partition P/S, unknown classes/kinds or ambiguous ownership block until reviewed; outgoing schema/type/role references alone do not imply external incoming users.

TRUNCATE uses actual FK endpoint/owner metadata and topology/trigger facts, not blanket view/type dependency rejection. Append/data-only use typed columns/constraints/defaults/triggers; enum reuse requires exact namespace/typeOID/kind/order and USAGE. This query supplies prerequisites, not a generic catalog-to-DROP CASCADE simulator or automatic mutation plan. Dynamic/string-bodied function references are untracked, event triggers can have arbitrary effects, and concurrent DDL can invalidate a snapshot; root must keep explicit refusals/quiescence/revalidation. No policy is enabled by this lease.

Native cases planned: multi-hop view→view plus parsed SQL function/composite signature; selected/unselected FK owners and exact column subids; outside defaults sharing selected-owned sequence; enum/domain/array/type function/column users; unused/empty enums with OID/label order; extension membership, shared role owner/ACL edges and global event roots; actual unsupported pg_policy/statistics flags without pg_catalog mutation. Known-empty headers must differ from missing/bad root IDs, denied type USAGE and actual query/decode errors. Tests use uniquely owned fixture setup/cleanup and read-only inspection; no product CASCADE behavior.
