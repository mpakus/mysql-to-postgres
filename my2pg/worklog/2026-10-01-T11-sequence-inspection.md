## Exact aliases/types and API — before code

Coordinator approved the direction and requires LEFT dependency joins so ordinary headers do not disappear. Both queries expose actual OIDs, catalog/subobject/dependency codes and quoted object identities; never parse sequence suffixes or function names to infer ownership.

Sequence query binds $1schema/$2table, both text. One row per deduplicated sequenceOID/boundColumnOrdinal binding × direct incoming/outgoing pg_depend edge; LEFT preserves a sequence header with no edges. Required aliases: sequence_oid/sequence_type_oid:u32; sequence_schema/sequence_name/type_schema/type_name/sequence_owner_role/bound_column_name/bound_identity_mode:String; bound_column_ordinal:i16; bound_default_expression:Option<String>; owner_table_schema/owner_table_name/owner_column_name/ownership_dependency:Option<String>; owner_column_ordinal:Option<i16>; start_value/increment_by/min_value/max_value/cache_size:i64; cycle/can_alter/can_use/can_select/can_update:bool; extension_name:Option<String>.

Optional dependency aliases: dependency_direction/dependency_kind/dependent_catalog/referenced_catalog:Option<String>; dependent_oid/referenced_oid:Option<u32>; dependent_sub_id/referenced_sub_id:Option<i32>; dependent_type/dependent_schema/dependent_name/dependent_identity/referenced_type/referenced_schema/referenced_name/referenced_identity:Option<String>. Optional incoming-default provenance: default_reference_schema/default_reference_table/default_reference_column/default_reference_expression:Option<String>, default_reference_ordinal:Option<i16>. Catalog names are qualified actual class identities, and sequence direct edges include unknown classes/kinds across schemas. This is direct-edge inventory, not a complete recursive graph safety claim.

State read API proposal: `read_sequence_state(client,&qualified_discovered_sequence,can_select)->Result<SequenceStateObservation,TargetError>`, where `Known{last_value:i64,is_called:bool}` differs from `Unavailable{reason:"select_privilege_denied"}`. Use safely quoted `SELECT last_value,is_called FROM schema.sequence` when SELECT is positively observed; no state query otherwise. Unexpected SQL/decode errors propagate. A permission change since metadata is an execution error/explicit newly denied observation, never fabricated known state. Option without an unavailable reason is insufficient to distinguish uninspected from denied.

Trigger query binds $1schema: text and $2table: nullable text. **Non-NULL $2 returns only triggers for that exact schema/table; NULL $2 returns all database event triggers**, because any enabled DDL event trigger can affect the chosen namespace. No implicit filtering by function schema or command-tag interpretation. LEFT direct trigger/function dependency joins preserve normal headers. Required aliases: scope/trigger_name/enabled:String; trigger_oid/function_oid:u32; internal:Option<bool>; table_oid/constraint_oid/trigger_parent_oid:Option<u32>; table_schema/table_name/constraint_name/definition/event:Option<String>; event_flags:Option<i16>; event_tags:Option<Vec<String>>; function_schema/function_name/function_arguments/function_identity/function_definition/function_language/function_volatility/function_owner_role:String; function_security_definer:bool; function_config:Option<Vec<String>>. Trigger function_definition is raw catalog text for coordinator's existing sha2 hashing; no function executes and no pgcrypto dependency is added. Internal triggers remain inventoried and separate from user triggers; event headers use internalNone rather than inventing a table-trigger value.

Trigger dependency fields use the same optional endpoint alias/types as sequences plus dependency_subject:Option<String> (trigger/function). Every direct incoming/outgoing pg_depend edge to either object is retained and unknown classes remain visible. Function dynamic/external references are not generally recorded by PostgreSQL catalogs; definitions/provenance permit review, not automatic safe-effect claims.
