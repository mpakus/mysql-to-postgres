## Chosen behavioral proof

Add a separate ignored native CLI case. Create an InnoDB MySQL `SMALLINT AUTO_INCREMENT` table, store `32767`, and set/observe its next AUTO_INCREMENT value as `32768`. Run the default MySQL-to-PostgreSQL mapping to a fresh target schema. Require the real source inspector to observe `Some(32768)`, require `IDENTITY_RANGE` and a nonzero CLI outcome, and prove PostgreSQL created no destination schema. This verifies the source-generation boundary is rejected before target DDL; it does not claim that source row data is unrepresentable or test all widths/server lanes. If MySQL 8.4 does not expose the exhausted next value through the inspected metadata, record that runtime limit and do not weaken the assertion.
