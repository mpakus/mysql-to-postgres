## Chosen implementation and acceptance

- Build the single `my2pg` release executable with the pinned Rust toolchain in a builder stage; use the pinned multi-platform Debian image for a small non-root runtime. Do not include reference repositories, development tests, Lisp, Clojure, a JVM, or database servers.
- Ship the Dockerfile and ignore rules in the source package. Preserve the existing root license and generated dependency notices in the image.
- Extend only the disposable TLS fixture certificate SANs with `mysql` and `postgres`, so the container can reach the existing services through their isolated Compose network while retaining `verify_full` validation.
- Add an explicit runner that builds a unique local image, starts the existing owned MySQL 8.4/PostgreSQL 16 fixture, runs a full migration of the deterministic `users` table from inside that network, independently checks row count, exact binary/decimal/text values and report completion, then stops only the fixture project and removes only the test image.
- Validate root/non-root image metadata and assert `java`, `sbcl`, and `clojure` are absent in the runtime image. Keep the default command as the existing CLI, so operator arguments remain unchanged.
- Run the dedicated container smoke on native Docker Linux/arm64, package-boundary tests, offline all-target Rust tests where appropriate, source-scope tests, and `git diff --check`. A passing local arm64 image does not certify amd64, hosted CI, release publication, cross-host reproducibility, or the outstanding legal review.
