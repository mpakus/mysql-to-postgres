## Chosen adaptation and proof

Replace the old unconditional setval SQL with a generated, qualified server-side block that locks the selected table before re-reading the actual column-owned sequence, type/options/ownership/privileges, non-consuming state and loaded maximum. Compute the next value using exact numeric arithmetic as the maximum of current next, source AUTO_INCREMENT, loaded MAX+1 and sequence minimum. Refuse exhaustion, cache/cycle/increment drift, missing/shared/unowned bindings and privilege failures before setval. Leave an already sufficient sequence's `(last_value,is_called)` unchanged. Every required failure remains fatal; setval effects remain explicitly nontransactional.
