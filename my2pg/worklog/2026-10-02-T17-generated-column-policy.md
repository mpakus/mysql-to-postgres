## Chosen behavior and proof

For a source column with `generation_expression`, resolve the exact override ID `<source database>.<source table>.<source column>`. `target_expression` means a PostgreSQL expression supplied by the operator: retain it in `ColumnPlan.generated_expression`, set `copy=false`, and emit PostgreSQL `GENERATED ALWAYS AS (<expression>) STORED`. `materialize=true` means intentionally create an ordinary target column and copy MySQL's already evaluated value; do not attach a generated expression. Missing policy or any non-affirmative/unsupported action remains a blocking `GENERATED_POLICY` diagnostic. Do not translate the source expression or broaden the SQL fragment surface. Existing validation owns fragment hygiene.

Add pure planner assertions for missing-policy block, target-expression DDL and COPY exclusion, and materialized ordinary-column DDL/COPY inclusion.
