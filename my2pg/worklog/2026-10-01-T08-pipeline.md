## Implementation and public API

- Async inspect(config, credentials) returns serializable Inspection {source,target}; async plan(config, credentials) returns MigrationPlan. Both inspect only, using the existing TLS transports.
- Async run(config, credentials, &mut Console, watch::Receiver<bool>) returns RunReport. PipelineError exposes exit_code()->u8: preflight 2, execution/I/O 1, interruption before execution 130. Display contains static classifications and planning diagnostic codes; driver DETAIL and credential values never enter the error.
- Planning precedes a database/session-scoped schema advisory lock, selected-source/target structural reinspection, read-only snapshot and append baseline capture. Dynamic estimates, row counts and auto-increment counters do not masquerade as structural changes. Cross-schema execution remains rejected until complete multi-schema inspection is implemented.
- Sequential COPY owns one batch with original row offsets and an aggregate retained permit, plus a separate row/parser workspace permit. Buffer capacities use batch_bytes and batch_rows. Raw and escaped row limits apply separately. Parser capacities come from D's encoder_workspace_bytes(maximum), rather than an assumed stack-only JSON implementation.
- Submitted batch row count and table index remain independent of rows_read. A bytes-triggered flush can retain a lookahead row; an interrupted COMMIT marks only submitted rows indeterminate. Previously acknowledged batches remain committed. No interrupted batch is replayed.
- Same-TLS ShutdownHandle.cancel closes the target protocol task after bounded cancellation and the source socket guard is dropped before file/output work. Interrupted pre-COMMIT DDL keeps its object in a warning diagnostic rather than falsely adding a failed execution step. Acknowledged server failure remains known even when subsequent rollback fails.
- The final typed report is persisted before Console::outcome. Closed output fails the operation and persists a failed report when the filesystem permits. Failed persistence propagates; there is no fabricated success report.
- Transform statistics use original source column names, with the resolved transform found in plan.json. Counters record converted rows whose explicit transform changed the value; NULL never increments. Values 0/1 retain equivalent Boolean semantics under tinyint-to-boolean; noncanonical integers count as changed. Currently implemented transform names are checked before writes.

## Actual validation

Owned fixture: target/integration/my2pg-mysql84-pg16-e8f44e8d3e01/connections.json, Oracle MySQL 8.4.11 and PostgreSQL 16.15, verified TLS. Only synthetic disposable data was modified; the public.users id999 sentinel remained must-survive. The owned services and volumes were stopped after testing; metadata confirms state=stopped. Artifacts remain for inspection.

Command: RTK-wrapped environment load followed by bin/cargo test --locked --test integration t08_pipeline -- --ignored --nocapture. Final run: 9 passed, 0 failed, 1.08 seconds (tool session 30064). Ordinary all-target Clippy with warnings denied also passed (session 96815).

The nine independent runtime cases prove:

1. Read-only inspection/planning creates no target schema; full mode commits seven rows across binary, duplicate-preserving keyless and quoted identifiers, schema-only copies zero, unsupported concurrency and an insufficient workspace budget reject before writes.
2. A later NUL conversion failure retains one acknowledged row, reads two, marks one unresolved, returns 1 and persists the same accounting.
3. Another session's migration advisory lock returns 2; a report base that is an existing regular file returns 1; neither creates the target schema.
4. An observer confirms actual active COPY before cancellation; a synthetic sleeping BEFORE trigger holds the operation. Cancellation returns 130, commits zero and leaves one read row unresolved.
5. During actual COPY, a separate source admin inserts a second row. The same source snapshot used by verification still sees one; migration verification completes while a fresh source count is two.
6. A real CLI subprocess with a closed JSON stdout pipe exits 1, persists a failed report and creates no target schema.
7. A deferred constraint trigger holds actual COMMIT, observed through pg_stat_activity. Cancellation returns 1/Indeterminate with two rows read, only one submitted row indeterminate, one lookahead unresolved and zero acknowledged commits. The target contains zero rows afterward; that later observation does not erase the required conservative uncertainty.
8. A fixture SHARE lock permits catalog reads while blocking planned TRUNCATE. Interruption returns 130, leaves failed_steps empty, records the interrupted object and preserves the existing target row.
9. Explicit empty-string-to-null converts one empty string while original NULL remains unchanged; two target NULLs and one recorded changed row are checked. A recognized but unimplemented transform rejects before schema creation.

The initial DDL cancellation observer falsely timed out because PostgreSQL cached its first statistics snapshot inside the transaction holding the fixture lock. No matching worker activity was visible in that stale snapshot. The fixture now clears its statistics snapshot each poll; the intended blocked TRUNCATE and cancellation were then observed. This was a fixture defect, not evidence of successful cancellation before the corrected run.
