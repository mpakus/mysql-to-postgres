## Chosen acceptance

Extend the existing disposable Linux FUSE fixture with an opt-in one-shot stall of `report.json.tmp` sync. Run the actual `DurableArtifacts` child worker with its report directory on that mount: first persist generation 1, then stall generation 2 at real `fsync`, invoke shutdown with a short deadline, and prove the caller returns within the bound with generation 1 still confirmed and the operation sequence still pending. Release the FUSE callback, verify the owned child is reaped, and confirm the previously acknowledged immutable and ordinary reports retain their exact bytes. All waits are bounded and the fixture releases/unmounts only its own mount even on assertion failure. Run the case only in a privileged Linux container with `/dev/fuse` and libfuse3; keep it ignored in normal integration runs.

If the operating system cannot interrupt the stalled syscall after the owned worker is killed, record that exact behavior and change the product supervision or its claims rather than passing a simulated timeout as physical acceptance.

## Implementation and acceptance result

- Added an opt-in SIGUSR2 one-shot stall to the disposable FUSE helper. It blocks only the next `report.json.tmp` `fsync` callback, signals entry through the fixture's private backing directory, and has a 10-second fail-closed timeout. The helper now supports hard links, which the production writer requires to retain immutable report generations; the existing T12 EIO behavior remains SIGUSR1-controlled.
- Added an ignored Linux integration case alongside the production artifact-worker tests. It starts the actual worker protocol with its artifact directory inside the FUSE mount, durably writes report generation 1, drives generation 2 until its actual `fsync` callback blocks, and invokes `DurableArtifacts::shutdown` with a 150 ms deadline.
- The case passed in the privileged Linux/arm64 container using the pinned Rust 1.99.0 builder and Debian bookworm FUSE3 packages: `cargo test --offline --locked --features artifact-worker-tests --test integration t15_artifact_io::production_worker_stalled_fsync_returns_only_the_confirmed_report -- --ignored --exact --nocapture --test-threads=1` — 1 passed, 153 filtered, 13.58 seconds. Shutdown returned under 750 ms with report generation 1 and sequence 1 still confirmed and sequence 2 pending. The ordinary and immutable report bytes stayed identical before and after release; the unacknowledged operation returned an error and the owned worker was reaped. Explicit FUSE unmount and fixture cleanup passed.
- The existing `t12_fuse_eio::linux_fuse_fsync_eio_preserves_the_last_durable_report` control passed with the helper extension before the hard-link capability was added; the final production-stall case exercises the final helper version. The first attempts exposed two test-fixture issues (the FUSE passthrough lacked the report worker's required hard-link operation, and the test did not poll the operation while awaiting the stall marker); both were corrected before the accepted run.
- `cargo fmt --all -- --check` and `git diff --check` pass. This proves local physical-stall shutdown behavior in Docker Desktop's LinuxKit kernel, not hosted CI or native Linux-runner execution; those distribution gates stay open.
