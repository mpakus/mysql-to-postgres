## Current defect boundary

All RunArtifacts APIs are synchronous. Pipeline startup create/write_plan/initial write_report, ReportOwner.persist, producer reject_conversion, recovery reject_copy, final flush/report replacement and renderer-failure report replacement can block a Tokio polling thread. Current ReportOwner publication comment relies on there being no await; simply making write_report async makes stale snapshots possible. RecoveryContext.observer is a synchronous FnMut and publishes report snapshots after committed/rejected deltas; its acknowledgement semantics must remain intact.

One spawn_blocking per operation is insufficient: it leaves live blocking tasks, Tokio shutdown waits, cancelled callers can drop byte permits/reservations while the operation continues, and repeated operations/runs can accumulate threads. One dedicated std thread improves cooperative DB cancellation but cannot satisfy bounded worker join or prevent late artifact mutations after library return unless the entire process is poisoned. Coordinator agrees the owned child is the stronger practical boundary.

## Minimal complete design proposal

One owned child process per admitted migration, and one parent async actor supervising that child. Use the same my2pg executable in an internal worker mode, intercepted before user CLI dispatch; no credentials or databases are passed. Bootstrap over private inherited stdin/stdout pipes with directory/root/table IDs and limits. Child stdout is binary protocol only, never the user's JSON stdout; stderr is null or one bounded static operational diagnostic. Child exits on malformed input or EOF; no arbitrary SQL, shell or source evaluation.

The worker exclusively owns artifact files and performs the existing synchronous writer operations. It streams document/reject bytes through the existing fixed16KiB buffer rather than decoding a document into a second model/JSON DOM. Keep existing private directory/file modes, generated table-ID validation, exclusive plan creation, atomic report temporary replacement, data-before-metadata sync and poisoning.

Only one admitted command exists total, including active work, queue and pipe payload. Parent channel capacity1 plus a single owned operation permit acquired BEFORE snapshot cloning/serialization prevents one hidden payload per waiter. The permit covers the operation until validated ACK/failure or terminal unknown handling. Waiting producer/consumer row/batch memory remains under the existing scheduler permits. No task/thread per command; no unbounded ACK vector or error log.

Finite binary framing proposal: fixed80-byte header: magic8, version2, operation1, reserved1, sequence8, report generation8, table ID18, reserved2, COPY offset8, data length8, metadata/document length8 and parent-confirmed report generation8. Operations are Create, Plan, Report, ConversionReject, CopyReject, Flush, Close. No body exceeds the admitted per-operation limits; reject wrong magic/version/kind/length/sequence/generation before file mutation. Header integers are explicit big-endian, checked arithmetic; EOF mid-frame is failure. COPY data streams first, metadata second; request sequence and per-table confirmed offset allow the parent to encode the exact existing metadata without asking child to parse untrusted arbitrary JSON. Child verifies header table/offset/length consistency and receives only the typed parent's serialization. Conversion metadata retains current raw bytes hex and IEEE float-bit encoding.

Response is a fixed48-byte frame: magic8, version2, result2, sequence8, durable report generation8, resulting COPY offset8, errno4 and reserved8. Success is sent only after all required file/directory sync calls return success. Pipeline row counters do not treat enqueue, pipe-write success, request acceptance, rename alone or process exit as durable acknowledgement. Any protocol error/partial frame/child death is a run failure; never replay the accepted operation. Report generations strictly increase and child refuses stale generation; publication ordering is also established in parent before capturing the snapshot.

Report-prefix preservation needs one small addition beyond the current writer: retain the parent's last ACKed report as an immutable generation-named file while publishing the next generation and replacing report.json. Rename followed by failed/stalled directory sync can leave report.json showing an unacknowledged generation; the existing atomic replacement alone does not guarantee old bytes survive that phase. The next admitted request piggybacks the parent's confirmed generation, allowing older generation files to be removed. With one operation admitted, at most the confirmed and next generation plus one temporary document are retained. Shutdown evidence identifies the confirmed generation file, not merely whatever report.json happens to contain. Never delete the confirmed generation on a failed operation or lost ACK. Existing report.json remains the ordinary successful-run interface; root must approve this explicit evidence-path addition.

Resource decision needed from coordinator before implementation: exact row/COPY storage permits survive in actor ownership, including locator/key/diagnostic/metadata bytes. Encode reject metadata with the existing streaming serializer into a capped buffer after measuring and reserving its actual length; COPY uses retained immutable BatchStorage/Bytes plus its permit, no row copy. Plan/report controls need a single separately admitted capped document buffer and16KiB serializer workspace; bound it before initial mutation and reserve control headroom so a full data batch cannot deadlock report publication. Derive the limit from the resolved plan/report sizing and migration memory admission, rejecting impossible configurations without changing sizing. Do not invent an undocumented unlimited "metadata exemption", guessed multiplier, or new user setting. Existing catalog/model memory remains a separately measured cost; this increment cannot claim total RSS is bounded solely by encoded bytes. Child adds one fixed buffer, fixed headers and bounded table-file/offset metadata; its RSS belongs in the process-tree measurement.

## Concrete API seam for review

Keep the synchronous RunArtifacts implementation usable for existing direct writer tests/internal child operations; production pipeline uses a new concrete DurableArtifacts facade, not a generic sink hierarchy.

Proposed public shapes (names can be coordinated):

- DurableArtifacts::start(base, limits, table_ids) -> async Result<Self, ArtifactError>; run_id/directory accessors become available after successful Create ACK.
- reserve(&self) -> async Result<ArtifactLease, ArtifactError>; one lease exists total. Construct owned document/reject payload only while holding this lease and associated memory permits.
- lease.write_plan(owned_plan_bytes), lease.write_report(generation, owned_report_bytes), lease.reject_conversion(owned_record_bytes, OwnedRejectTicket), lease.reject_copy(retained_storage, range, owned_record_bytes, OwnedRejectTicket), lease.flush() -> async result with a typed receipt.
- shutdown(deadline: Instant) -> async ArtifactShutdown {last_acknowledged_sequence, last_durable_report_generation, pending_operation, child_exit, unreaped_pid}; consumes/stops admission, drains an outstanding response within the common shutdown deadline, requests owned-child termination when exceeded, waits only within the remaining deadline. Drop never synchronously waits and never claims cancellation.
- A bounded per-table durable-reject ledger records confirmed count and last applied operation; actor commits the owned rejection reservation and publishes that ledger BEFORE notifying the caller. No per-row history is retained.

Recovery RejectBudget must offer owned reservations backed by Arc so the actor can hold them across a dropped caller future. The actor owns accepted operation payload/reservation; callers cannot release/reuse them on cancellation while writes continue. At a terminal cutoff, no new rejects/runs are admitted; reservations without ACK are not reported as durable rejects. A late physical record is an unacknowledged suffix, not justification to silently update a report that already returned.

Recovery's observer should keep its critical state merge synchronous and split async persistence from it. Smallest concrete replacement is a callback update(progress)->io::Result<PublicationRequest> plus an awaited publisher, or a crate-local RecoveryObserver with exactly update and async publish methods; root/C choose one concrete seam. On COPY success, merge committed rows/bytes, clear active state and record previous progress BEFORE any publication await. On reject ACK, merge the durable ledger delta BEFORE the next await. C retains the existing original-batch active/pending accounting and recovery safety policy. Async producer rejection awaits the same facade and shared budget.

ReportOwner needs an async publication gate acquired BEFORE taking its current report snapshot and assigning generation. It must release its authoritative report mutex before serialization/I/O, avoid holding std mutex guards across awaits, and apply durable-reject ledger deltas exactly once by operation sequence. Finalization reconciles the actor ledger even if a worker's receipt future was dropped. This prevents a physically acknowledged rejection from disappearing because cancellation won the caller's select, and prevents an older snapshot overwriting a newer one.

## Cancellation, reaping and repeated library runs

Cancellation closes artifact admission and data scheduling, signals/cancels database workers concurrently, and keeps one supervised artifact actor draining the accepted request during the common10-second deadline. Responsive writer: finish the accepted sync, reconcile receipts, then publish/ACK final report and Close. Failed/stalled writer: do not enqueue Flush/Report behind it and wait forever; return explicit ARTIFACT_SHUTDOWN_UNKNOWN with last confirmed sequence/report generation and any outstanding rejection counted unresolved. Preserve COMMIT indeterminate classification independently. When final report cannot be acknowledged, console reports the last durable artifact snapshot and persistence failure; it cannot claim a new report was stored.

A sync may complete but the child may die before ACK delivery. That is unknown artifact durability, even if later inspection finds bytes; no automatic replay. A child may be killed after metadata bytes reach cache but before fsync; those bytes also are not an acknowledged rejection. Never rewrite earlier durable prefix or claim the entire reject file equals the acknowledged prefix after interrupted I/O.

Use tokio::process child ownership and kill_on_drop as a fallback, plus explicit start_kill/wait bounded by the common deadline; it requires coordinator addition of Tokio's existing process feature (no new framework). Do not kill arbitrary PIDs or process groups. Never discard an unreaped Child handle. A process-global single live writer lease remains held by the supervising actor/reaper until the actual child is reaped; after timeout one bounded reaper remains, and subsequent library starts fail immediately while the lease is occupied. CLI return can request termination; SIGKILL does not guarantee kernel-uninterruptible child disappearance, process-tree quiescence or successful fsync. PID/sequence/outcome remains accurately owned/reported. No replacement child/thread may be spawned merely because a timeout returned.

Library startup must know a compatible worker executable: env::current_exe is valid for the CLI but not arbitrary embedding/test binaries. Explicit worker executable is an internal startup parameter, validated protocol handshake required; default CLI supplies its own executable. Do not secretly execute the embedding application as a worker or advertise arbitrary library embedding support. Same-process tests can launch their test child entry calling the concrete worker serve function.
