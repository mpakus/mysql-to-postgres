## Selected regression boundary

Use one InnoDB source table and one target table in Full mode with `consistency = single_snapshot`. An event-trigger/advisory barrier on the real target `CREATE TABLE` lets source preflight and snapshot setup finish first. While the target command waits, the fixture admin takes `LOCK TABLES <owned table> WRITE`, then releases the target barrier. The observer records the exact migration-user MySQL connection ID whose actual table SELECT is in a metadata-lock wait state. After cancellation, require that same server thread to disappear while the runner terminates and the fixture lock-holder remains alive; only then release the owned lock. Finally assert exit 130, zero rows read/committed, no indeterminate/unresolved work, a persisted cancelled report, and cleanup of only its unique objects.

The initial live run confirmed the cancellation limitation: cancellation completed the client run, but MySQL still reported the source statement waiting on the external metadata lock. The required case was strengthened to require server-thread disappearance before fixture lock release.
