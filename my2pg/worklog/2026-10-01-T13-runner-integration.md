## Draft implementation and measured limits

Production uses scoped FuturesUnordered table futures with checked Admission/Resources, separately bounded mpsc queues, one global RejectBudget and immutable batch permits. SingleSnapshot transfers the control target shutdown handle to its active table registry (avoids duplicate cancellation sockets), keeps the original source transaction and uses one pipeline. Generated non-FK finalize steps execute in independently bounded table groups; dependent FK steps and sequences follow the index barrier. Per-table active COPY slice/stage/clock and per-index DDL step registry survive dropping the execution future.

The short authoritative report mutex is released before every filesystem/network operation. ACK/reject callbacks merge deltas, avoiding overwrite of a concurrently durable producer reject. Snapshot publication is synchronous in the same scoped execution poll, so an older snapshot cannot overwrite a newer snapshot across an await. Worker exceptions are caught; teardown collectors rank Indeterminate > Failed > Cancelled, retaining the first diagnostic at equal priority. Control DDL and verification have stop-aware polling, so user-only cancellation does not become an incidental aborted-connection failure. Both source and target teardown run; a close failure cannot replace an already observed fatal pipeline fault. Shutdown shares one deadline and dispatches cancellation once; deadline diagnostics retain a failing code/message **already returned to the collector**. A stop published before its fatal worker returns can still exhaust the source-kill deadline before the collector receives that cause; this edge is an explicit open gate below.

**Filesystem limit:** synchronous report fsync and durable reject writes block the cooperative execution thread. Tokio's 10-second shutdown timeout cannot preempt a stalled filesystem syscall. No bounded cancellation claim is made under stalled filesystem I/O; this is an explicit remaining gate, not a passed helper assertion.
