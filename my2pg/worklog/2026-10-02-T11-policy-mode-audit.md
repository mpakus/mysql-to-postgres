## Remaining concrete gaps to resolve

1. **Data-only `on_existing="error"` is accepted and behaves like an unlabelled append.** `src/config/validation.rs:250-270` rejects append outside data-only and recreate in data-only, but imposes no matching requirement that data-only choose append or truncate. `src/plan/mod.rs:994-1002` emits `TARGET_EXISTS` only outside data-only. `src/plan/tests.rs:97-124` includes `(DataOnly, Error)` in the accepted-observation branch, while the architecture says append is an explicit data-only operation (`docs/architecture.md:74`). Decide the contract: either reject this combination in config/planning, or document it as intentionally equivalent to append. Add one real CLI case against a pre-populated target with a trigger/unique constraint to prove the chosen behavior and report wording; also assert source and pre-existing rows remain unchanged on the selected policy's failure path.
2. **Existing-target `schema_only + recreate` has planner/privilege coverage but no runtime proof.** `tests/cases/t11_existing_policies.rs:1035-1040` only expects a planner privilege diagnostic under this combination. The full/schema-only runner (`t11_structures.rs:39-49`) creates new schemas; the native recreate path at `t11_existing_policies.rs:243-289` is full mode. Add a CLI case that starts with a selected table and owned extra CHECK/index/trigger plus an outside sentinel, runs schema-only recreate, and asserts: selected schema/constraints/indexes are recreated, the selected table has zero rows, identity metadata can generate safely, and outside objects/data survive. Also exercise `schema_only + error` against an existing selected table and assert it refuses before mutation.
3. **No native `data_only + truncate + reset_sequences=true` cross-policy proof.** The reset-enabled stale-sequence case is append (`t11_monotonic_sequences.rs:403-445`); truncate is only exercised with `reset_sequences=false` (`:451-464`), and the policy truncate case has no identity column (`t11_existing_policies.rs:170-210`). Add a runner case with an existing row and deliberately stale sequence, truncate the selected FK-closed set, load source rows, and assert exact retained/replaced rows, surviving trigger/constraints, monotonic sequence state, and next generated value. Include an outside/nonselected table whose sequence dependency or rows must remain untouched.
4. **Policy checklist remains intentionally open even though broad subcases now pass.** The remaining gaps above explain why `docs/checklists.md:64` should not yet be checked; no board/checklist edits were made in this audit.
