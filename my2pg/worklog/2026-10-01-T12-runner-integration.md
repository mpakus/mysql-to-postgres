## Chosen adaptation

- One `RejectBudget` per run is shared by conversion and server COPY rejects. Reserve before writing and count only after the real durable writer succeeds. Exceeding the cap is a required failure; exact-limit completion remains partial.
- Existing retained targets are checked for recovery safety before target mutation. Created/recreated targets are checked by the production helper before COPY. No caller-manufactured rollback/safety flag is introduced.
- The synchronous recovery observer immediately applies per-batch cumulative deltas and publishes only active subrange rows before another await. Persist snapshots after acknowledged/durable progress. Cancellation or a later failed COMMIT retains earlier acknowledgements; unknown rows are never replayed.
- Use the converter's semantic effect helper for all supported named transforms, after successful encoding. NULL and representation-only conversions are not counted as explicit changes. Transformation counters describe successfully converted source values, including a row that subsequently fails target COPY.
- Successful execution with rejects sets table/run `Partial`; counts/schema verification still checks source accounting and target baseline plus committed rows. Existing execution/cancellation/verification exit precedence remains unchanged.
- Prove behavior through the actual executable and production transports: conversion plus server rejects, exact global limits across tables/batches, stop mode, original locators/bytes, redaction/private artifacts, and cancellation after partial recovery. Keep module-only evidence separate from runner acceptance.
