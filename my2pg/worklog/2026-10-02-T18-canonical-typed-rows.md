## Selected supported set and acceptance

Expose independent functions from the new module: canonicalize a MySQL `RawValue` row through the existing conversion contract, and canonicalize target values obtained from an explicit PostgreSQL `::text` projection. The supported kinds are signed integer, unsigned integer, decimal, text, and boolean. Integer output becomes a checked signed 128-bit value encoding (large enough for MySQL `BIGINT UNSIGNED`); decimal is normalized with exact decimal-string rules and no floating conversion; text preserves UTF-8 bytes after the source converter's approved transformation; booleans accept the converter's `false`/`true` and PostgreSQL's documented `f`/`t` text forms. Each field uses a kind tag, NULL/present tag, and length-delimited payload. Unsupported kinds, malformed text, unsupported decimal exponents, width mismatch, and conversion failure return typed errors that do not include data values.

Independent tests will compare source and target canonical bytes for values, transformations, and NULL/empty distinctions; detect same-count changed values; and reject unsupported kinds and malformed values. No test reuses the implementation to generate its own expected row bytes.

This slice does not add the live PostgreSQL projection builder/reader, bind scans to the migration snapshot, address append baselines, handle all `ValueKind`s, connect comparison results to durable reports, or remove the runner's current Content rejection. T11/T13/T15 gates and complete T18 acceptance remain open.

Converter escape review: direct source inspection confirmed `encode_value`'s doc/API at `src/convert/mod.rs:262-276` produces logical (unescaped) values, while COPY control-character escaping is applied separately by `Representation::write_copy` from `encode_row_limited`. `Representation::visit` forwards decoded text bytes. The new escaped-control test checks actual tab/newline/carriage-return/backspace/form-feed and literal backslash sequences against PostgreSQL `::text`, including an assertion that an actual tab differs from literal `\\t`. Binary remains unsupported because `Representation::visit` renders binary as a PostgreSQL bytea input literal (`\\x...`), which would require a separately reviewed typed projection/decoder.
