# T22 — Static MySQL 5.7 applicability audit for T15–T20

## Scope and method

Read-only review of every T15–T20 ID in `MYSQL_CASE_INVENTORY`, comparing the Rust test setup and source SQL with the pinned MySQL 5.7.44 lane. No harness/test edits, index refresh, database startup, container startup, or runtime DB test was performed. The recommendations below are static applicability decisions only: `run_candidate` means no MySQL 5.7 source-side syntax/feature blocker was found and the case should be eligible for a later native lane; it does not mean the behavior has passed at runtime. `not_applicable` is limited to a source feature used by the test that 5.7 lacks. There are no `needs_runtime` cases in this family: static inspection was sufficient to find a concrete applicability boundary for the excluded cases, and the remaining source SQL is ordinary 5.7-compatible SQL or a documented 5.7 feature.

The checked-out my2pg HEAD is `db28c459a8a3caf45b07e9e72bcbc9fd3194c762`; it contains extensive working-tree changes, so this report is tied to that HEAD plus the inspected current working files, not asserted as a clean commit snapshot. The T22 pin diagnostic records the pinned 5.7 image as MySQL `5.7.44-1.el7` (`mysql:5.7.44`, linux/amd64). The full project index reports that same my2pg revision.

Additional authoritative version checks:

- MySQL 5.7 [ALTER TABLE documentation](https://dev.mysql.com/doc/refman/5.7/en/alter-table.html) states CHECK clauses are parsed but ignored by every storage engine. The T17 test requires the catalog to report its source CHECK as enforced.
- MySQL 8.0 [CREATE INDEX documentation](https://dev.mysql.com/doc/refman/8.0/en/create-index.html) says functional key parts are supported in MySQL 8.0.13 and later. The T17 source setup creates a unique index on `LOWER(email)`.
- MySQL 5.7 [spatial argument handling](https://dev.mysql.com/doc/refman/5.7/en/spatial-function-argument-handling.html) documents empty input as `GEOMETRYCOLLECTION()`. The earlier MySQL [WL#2381](https://dev.mysql.com/worklog/task/?id=2381) records that the `EMPTY` WKT keyword was not supported. Both spatial tests call `setup_source`, which inserts `ST_GeomFromText('GEOMETRYCOLLECTION EMPTY',0)` at `tests/cases/t17_spatial.rs:101–106`; consequently the shared source setup cannot run unchanged on 5.7. This does not claim that all MySQL 5.7 spatial shapes or SRIDs are unavailable.
- MySQL 5.7 [generated-column documentation](https://dev.mysql.com/doc/refman/5.7/en/create-table-generated-columns.html) documents generated columns. Test expression `LOWER(source_text)` is a supported deterministic native expression.
- MySQL 5.7 [miscellaneous function documentation](https://dev.mysql.com/doc/refman/5.7/en/miscellaneous-functions.html) includes `DEFAULT(col_name)`, which the T16 test probes.

## Outcome and limits

Complete family inventory: **29 IDs**; recommendations: **25 `run_candidate`**, **4 `not_applicable`**, **0 `needs_runtime`**. The exact four excluded IDs are the T17 enforced CHECK case, T17 functional-index case, and both T17 spatial cases. This family audit does not change `MYSQL57_NOT_APPLICABLE`, the per-lane manifest, source fixtures, or overall MySQL 5.7 lane status. The coordinator should merge only reviewed reasons into the shared harness, then rerun database-free inventory/preflight tests. A native MySQL 5.7 run is still required to establish behavior for candidates; nothing in this worklog is a runtime pass.
