## Chosen adaptation and proof

Add a pure std-only iterator over inclusive `IntegerKey` endpoints. Convert signed values to ordered `u128` coordinates by offsetting from `i64::MIN`; use raw `u128` coordinates for unsigned values. A caller supplies the maximum **key-space span** per range, not an asserted row count. This keeps sparse-key behavior honest and leaves the unresolved `rows_per_range` config policy to the coordinator's T20 integration. Both missing MIN/MAX values represent an empty table; partial bounds, mixed signedness, reversed bounds, and zero span are errors. The iterator advances only after emitting a range and uses checked wide arithmetic; it never constructs `max + 1`. Each range is closed/inclusive, which lets the later MySQL query use `pk >= lower AND pk <= upper` without a representable successor requirement.

Colocated tests will verify empty/single-row input, signed/unsigned extrema including `u64::MAX`, an uneven final range, sparse-key exactly-once coverage, exhaustive small-domain partition properties, and invalid inputs. Compile/run these tests as a standalone Rust test crate because the coordinator explicitly owns `src/pipeline/mod.rs`; module registration and database-level exact multiset tests are integration follow-ups. No shared contract change is needed for this pure module, but runner integration must decide the `rows_per_range` to `max_key_span` mapping, enforce frozen consistency and source PK metadata, and keep task creation lazy/bounded.
