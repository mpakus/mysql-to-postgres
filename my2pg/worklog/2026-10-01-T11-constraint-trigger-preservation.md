Primary PostgreSQL16 sources:

- [pg_constraint](https://www.postgresql.org/docs/16/catalog-pg-constraint.html) documents user constraint triggers as ordinary catalog entries with contype='t'; conkey is not their column map. convalidated may be false only for FK/CHECK. Deferral facts are typed booleans.
- [pg_trigger](https://www.postgresql.org/docs/16/catalog-pg-trigger.html) links tgconstraint to that OID and identifies table, internal/user state, enabled mode and function. Its documented deferral redundancy has an FK exception; do not generalize a user-trigger branch to FK semantics.
- [CREATE TRIGGER](https://www.postgresql.org/docs/16/sql-createtrigger.html) defines constraint triggers as AFTER ROW on ordinary tables with statement-end or transaction-end firing. Their function may raise errors at transaction end; this is real COMMIT behavior, not an unsupported constraint kind invented by the fault test.

## Actual cause and available positive facts

bind_constraints groups actual pg_constraint headers by OID, then rejects every kind outside p/u/f/c and every deferrable/initially-deferred row. Consequently a valid deferred user constraint trigger is rejected twice by the same generic gate. inventory_recreate similarly omits known kindt, but this investigation recommends no destructive-policy expansion as a side effect.

The current observations are sufficient for a **narrow preservation decision** without evaluating user code or inventing its behavior: each zero-key constraint header survives the LEFT JOIN, carrying nonzero constraintOID, kind, definition, validated/deferral booleans; trigger rows carry exact linked constraintOID/name, triggerOID, tableOID/schema/name, user/internal state, known enabled mode, event flags and complete function identity/definition. Trigger rows repeat per dependency edge, so deduplicate by triggerOID instead of demanding one raw row. The per-table query itself supplies the constraint's parent scope; it must match the linked trigger's positively observed table. No additional model field is required just to preserve this native object unchanged. Exact trigger timing comparison/reconstruction would require more metadata and is **not** claimed by this preservation branch.

## Smallest proposed policy fix

Add a kindt branch **before** the generic p/u/f/c/deferred rejection in bind_constraints. Permit preservation only when:

1. It has exactly one nonzero-OID zero-key header (ordinal/column absent), validated=true, coherent initially-deferred implies deferrable, nonempty actual definition and no contradictory per-part headers.
2. At least one linked observed trigger exists and all rows resolve to exactly one nonzero triggerOID, allowing repeated dependency rows. Their constraintOID/name matches this exact header, scope is table, tableOID/schema/name matches this existing target, internal=Some(false), enabled is one of O/D/R/A, definition/function identity are positively present, and repeated header facts agree. Existing ordinary-standalone/topology gates remain required; a cloned-parent trigger or unknown event/internal/header facts fail closed.
3. The target/source required FK/CHECK/index bindings still run independently. A kindt object must never satisfy a source FK, CHECK, PRIMARY or UNIQUE expectation.

Then continue out of the generic rejection for only that proved group. Use the existing TARGET_TRIGGER_PRESERVED warning and do not disable/drop/recreate the object. On missing/orphan/cross-table/inconsistent links retain an explicit blocking diagnostic (generic TARGET_CONSTRAINT_UNSUPPORTED is adequate; an additive specific code is optional). Non-t deferred/unvalidated/unknown constraints, invalid indexes, target privileges and topology stay gated exactly as before. This is preservation of a documented ordinary target object, not an arbitrary trigger-safety bypass.

Keep T12 safety unchanged: enabled user triggers remain blocked for reject/bisection, and a stop-mode deadlock/serialization retry still requires its actual catalog safety proof. Stop-mode initial COPY may execute ordinary user-trigger behavior once; a deferred server error must be classified by SQLSTATE/stage, never counted as ACK and never replayed if COMMIT is uncertain. Preserving a trigger's OID/definition does not certify its function as row-local, harmless or retryable.

DataOnly/append is the required narrow policy first. Existing apply path also handles non-destructive existing targets; any Truncate acceptance must retain the existing enabled ON TRUNCATE side-effect gate. Recreate may keep its independent unknown-kind rejection until its owned-drop policy is reviewed; do not broaden drop inventories just to restore the COMMIT test.
