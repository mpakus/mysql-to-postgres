## Implementation and current evidence

`verify_sequences` reads explicit generation expectations and actual `pg_sequence` increment/minimum/maximum/cycle/cache, then reads the qualified sequence's last_value/is_called and target MAX without calling nextval or setval. It compares the inferred next value to loaded MAX+1, source AUTO_INCREMENT, explicit next_minimum and signed limits using i128 arithmetic. Checks apply even when reset_sequences is disabled: disabling initialization cannot certify an unsafe generator. Unit-increment, noncycling, cache1 expectations can complete; missing/duplicate/nonidentity, nonunit/cyclic/invalid contracts and cached state remain Unsupported, while proved mismatches/exhaustion are Different. Idle/exclusive destination and absence of cached values held by other sessions remain operator contract assumptions, not remotely proved traffic isolation.

`verify_primary_key` now derives the target's ordered PK columns from complete typed primary-index expectations. Explicitly absent target PK is valid even when the reader retains the original source PK. Incomplete or ambiguous target PK expectations remain Unsupported. Other structure checks retain the current simple-btree scope; full general expression/index/generation semantics are later tasks.

## Typed literal default research — before coding

Coordinator's actual seven-table run found the safe empty-varchar default rendered as `''::character varying` while the plan records `E''`. XERJ `project-my2pg` / `default literal equivalence empty varchar` returned source default regressions; `ref-paganel` / `default postgres cast string literal`, followed by symbol `strip_pg_casts`, returned pinned `ced0a3c953bcf63bba6085bf2b8b9fc75cbbeddc`, `crates/engine-schema/src/type_registry.rs:170` and tests at366–401. Read the original string-aware cast stripping and adjacent literal-colon/quote tests, plus my2pg's actual `plan::default_sql`/`literal` and current verifier/default catalog query. Paganel strips casts broadly, including function arguments; reject that broad adaptation here.

Chosen narrow adaptation: parse only complete simple text, exact decimal/integer and boolean literals under the already approved target column type. Accept an optional cast only to that same built-in type/base; preserve quoted `::` as data. Decode only known string escapes; unknown syntax remains Unsupported. Compare fully parsed values, so changed literals become Different. Never evaluate defaults, invoke functions or parse arbitrary SQL. Unit and real PostgreSQL tests will cover empty/nonempty varchar, numeric/boolean values, quote/backslash/colon data and changed defaults; wider timestamp/JSON/domain/expression equivalence remains later T10.
