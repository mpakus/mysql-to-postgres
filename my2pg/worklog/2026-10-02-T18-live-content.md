## Chosen adaptation and acceptance

Implement a bounded append/finish API over the existing external merge sorter so async MySQL/PostgreSQL streams can be consumed one row at a time. Build exact canonical multisets, preserving duplicates and without trusting hashes. A follow-up requirement from the coordinator established the Append contract: capture each selected target table's exact typed rows in a private spill-backed `AppendContentBaseline` before mutation; preserve the handle through the run; then merge baseline ∪ migrated source and compare it with post-run target rows. Count-only baselines are insufficient. The verifier starts a source repeatable-read read-only snapshot for frozen mode, reuses an already-pinned single snapshot only when explicitly told by its caller, and scans PostgreSQL under a repeatable-read read-only transaction. Return Complete only for exact canonical equality and complete migration accounting; Different for content mismatch; Unsupported for unreviewed types, schema-only/invalid snapshot preconditions, or absent/mismatched append baseline; Error for transport, storage, or explicit cleanup failures. Source transforms are checked by comparing `convert::encode_value` output with actual target values. Memory and maximum canonical row size are explicit arguments because current report/config types do not expose them here.

Planned evidence: database-free acceptance for equal-count value corruption, duplicate multiplicity (including baseline union), transformed text, unsupported kind/mode, and status selection; native owned MySQL/PostgreSQL acceptance for actual streams, source snapshot, target repeatable snapshot, and exact report status when the harness is available. The pipeline hook must call `capture_append_baseline` before any target mutation for Append and retain its returned handle until it passes that handle to `verify_content`. It must also pass `memory_bytes`, `max_row_bytes`, and whether the source snapshot was already established. This vertical slice does not prove the runner invokes either API; T18 remains open until the root integration lease wires and validates the lifecycle.
