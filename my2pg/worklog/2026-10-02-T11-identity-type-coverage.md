# 2026-10-02 — T11 AUTO_INCREMENT integer type coverage

Status: focused native coverage slice; broader T11 acceptance remains open. Ownership: new `tests/cases/t11_identity_types.rs` only. The coordinator owns test module registration and the task board.

## Contract and acceptance

Cover every signed or unsigned MySQL integer width that the current mapping can safely represent with a PostgreSQL integer identity: signed/unsigned TINYINT, signed/unsigned SMALLINT, signed/unsigned MEDIUMINT, signed/unsigned INT, and signed BIGINT. For every source table, independently assert target type, imported values (including values outside the corresponding signed width for widened unsigned types), and the next generated PostgreSQL value against the source `AUTO_INCREMENT` metadata. Unsigned BIGINT AUTO_INCREMENT must refuse planning before target schema/table creation because `numeric(20,0)` preserves data but does not have a supported PostgreSQL sequence range. Do not test or claim unsigned BIGINT identity generation.
