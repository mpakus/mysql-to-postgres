## Chosen test adaptation and acceptance

After the schema-only setup, change source table 0 values to two distinct strings. Add an extra deferrable, initially deferred unique constraint to the already-created target table 0; T11 has a native plan acceptance for this exact class of extra target key. In a fixture-admin target transaction, insert a third row whose value conflicts with source row 1 and leave that transaction open. During the new DataOnly Append run, table 0's real COMMIT must wait on that transaction's deferred uniqueness check. Independently require `pg_blocking_pids` to show a blocker on the active COMMIT, then observe both sibling rows committed before requesting cancellation. The canceled report must retain the first table's attempted/indeterminate batch and the second table's acknowledged prefix. After proving the migration connections have closed, roll back only the fixture-admin transaction and verify the target contains no row from the canceled batch (no replay) while the sibling rows remain.

This changes only the test's lock mechanism. It keeps the current DataOnly target-inspection contract, exercises a real server-side COMMIT wait and cancellation, retains independent row/report checks, and adds no production seam, trigger exception, source abstraction, or database policy relaxation.
