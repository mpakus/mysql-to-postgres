## Chosen adaptation and proof

Reuse the single persistent std reaper as startup coordinator. Publish one global startup slot/Life/memory permit before notifying it; take the owned StartJob out of the mutex and run spawn outside every shared mutex. Keep the slot visibly starting with no known PID while blocked. Start caller awaits only an async receipt; cancellation guard records cancellation without waiting for spawn. After the owned spawn result arrives, retain/kill/reap its exact Child before permitting replacement. No second thread, spawn_blocking task or replacement startup accumulation.

Expose WorkerState.starting as local facade lifecycle evidence; normal data/report APIs and authoritative ledger remain unchanged. Main must inspect the exact private marker before normal Clap/runtime startup. Reject extra private arguments without printing them; worker stdout carries binary protocol only. Root launches current executable plus the marker; start already clears environment.

Independent test proposal: test-only std Command pre_exec callback performs a real blocking native read before exec, forcing parent spawn to wait on std's CLOEXEC handshake. Publish owned child PID through an already-open descriptor using only async-signal-safe syscalls; parent verifies startup remains visible/Busy and timers progress, drops start future, then releases the owned gate so coordinator receives/kills/reaps its Child. This proves blocked child handoff; it is not proof of a stalled executable filesystem or uninterruptible kernel disappearance. Fault plumbing remains confined to tests/support/artifact_worker.rs and default-off feature. Also exercise actual production executable Create/Plan/Report/Conversion/COPY/Close and malformed private argv/protocol, preserving normal --help.

Kernel-uninterruptible startup may remain leased indefinitely with unknown PID; deadline must not imply cancellation/reap. Resource formula will include the concrete StartJob/startup slot control sizes; opaque std Command/oneshot/kernel allocations retain the previously documented RSS boundary. No pipeline integration edits here.

## Implementation and verification

Implemented the handoff in `src/report/artifact_io.rs`: startup is installed as a single `ChildSlot` job, the persistent reaper calls blocking `Command::spawn` outside its mutex, and cancellation follows that same slot until it kills/reaps the returned child. `WorkerState.starting` makes a spawn with no known PID observable. The lock now has an explicit lexical scope before the asynchronous receipt wait, preserving a `Send` start future.

Added `cancelled_blocking_spawn_keeps_slot_owned_until_exact_child_is_reaped` to `tests/cases/t15_artifact_io.rs`. Its Unix `pre_exec` hook uses inherited socket descriptors and native `read`/`write` calls to hold the actual fork/exec handshake; it checks timer progress, starting/unknown-PID state, cancellation, and slot retention through reaping.
